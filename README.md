# I build things to find out how they work

Usually I find out the hard way. That seems to be the only way it sticks.

Everything in here started as *"how hard could it be?"* The answer is reliably **"harder than that."**
I keep asking anyway.

---

## Things I've built

### [grindz](https://github.com/ShockRock2004/grindz)

A workout tracker. React Native on Android, installable PWA on the web, one Supabase backend and one
image CDN feeding both. Log lifts, chase PRs, see what you actually trained instead of what you meant
to train.

Building the same app twice, once native and once for the browser, taught me more than building two
different apps ever would have. Shared data layer, two very different opinions about what a screen is.

### [kamar-taj](https://github.com/ShockRock2004/kamar-taj)

Claude Code skills I built because I got tired of not having them.

- **wong** reads a day of AI coding sessions and writes me a study guide. Letting an agent build things
  I can't explain is a bad long-term plan.
- **dormammu** refuses to call a bug fixed until it has watched the test pass with its own eyes.
- **agamotto** sends my work to a second, meaner AI and makes the two argue until one of them is right.

### [news-intelligence](https://github.com/ShockRock2004/news-intelligence)

Python, TypeScript, and a Dockerfile walk into a repo. Mostly an excuse to stop being scared of Docker.
It worked.

---

## The trail of evidence

```
todo-list  →  weekly-plan  →  workout  →  insight  →  news-intelligence  →  grindz
```

Vanilla JS and a lot of confidence at the start. TypeScript, native Android builds, and a CDN by the
end. The early repos are still public on purpose — deleting them would be editing the story, and the
gap between those and the current ones is the only progress report that matters.
